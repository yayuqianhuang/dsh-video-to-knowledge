# Release v0.1.18 · 交付口径改为 DOCX + Markdown，默认不出 PDF

## 这一版改什么

**成书默认交付 DOCX 与 Markdown，不再生成交付用 PDF。** 子链里的 `pdfFinal` 节点被移除。

之前每个版本都会顺手转一份 PDF，但实际用起来它是多余的：

- PDF 把排版结果**冻死**了，正文改一个字就得重排两遍；
- DOCX 能打开、能改、能打印，MD 能 grep、能进版本库——"读"和"改"两个场景已经覆盖；
- PDF 唯一不可替代的场景是"固定分页对外分发"，这属于偶发需求，不该是默认动作。

## 变化

| 项 | 之前 | 现在 |
|---|---|---|
| 交付物 | DOCX + PDF + MD | **DOCX + MD** |
| 成书子链节点 | 7 个（含 `pdfFinal`） | **6 个** |
| `pdfPass1` 的定位 | 为转 PDF 做准备 | **仅为量目录页码的中间件**，不交付、可删 |
| 没有 PDF 转换器时 | 最终 PDF 缺失 | 目录退化为无页码，DOCX 照常交付 |

## 仍然保留 PDF 能力

量页码这一步绕不开一份 PDF（两遍排版要靠它确定每个标题落第几页）。所以：

- `pdfPass1` 继续生成，但只写 `book/pass1.pdf`，不进 `reports/`；
- 真需要交付 PDF 时手动跑一次：

```bash
python pipeline/book_pdf.py --in reports/xxx.docx --out reports/xxx.pdf
```

## 冒烟

93 项全过，其中新增一条反向断言：**book 子链不得再出现 `pdfFinal` 节点**，且验收语句必须写明"不出 PDF"——防止以后又悄悄加回去。
