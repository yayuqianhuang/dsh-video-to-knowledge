# Release v0.1.17 · 发版工作流自愈（draft → published）

## 这一版修什么

上一版的 tag 触发发版工作流有个漏洞：**如果同名 Release 已存在（哪怕它是个 draft），工作流只 `gh release edit` 改正文，不会把它发布出去**——于是 Release 在外网看是 404，而 Actions 显示成功。

这次把幂等分支改成 `gh release edit … --draft=false`，已存在就更新正文并强制发布。

## 触发过程（真实踩到的）

1. 我先推了 `v0.1.16`，但那颗 tag 指在错误的提交上；
2. 删 tag、重推正确的 `v0.1.16`；
3. 删 tag 让 GitHub 上原有的 Release 变成 draft，第二次运行只更新正文、没发布 → 公开 API 返回 404。

## 顺带说明

- 正文来源仍是 `docs/releases/<tag>.md`，没有就走 `--generate-notes`；
- 鉴权仍是仓库内置 `GITHUB_TOKEN`（`permissions: contents: write`），不存任何长期密钥；
- 已发布的 Release 再推同 tag 会更新正文，不会重复创建。

## 验证方式

```bash
curl -s https://api.github.com/repos/yayuqianhuang/dsh-video-to-knowledge/releases/tags/v0.1.17 | jq -r '.name, .draft'
```
